## 1. 范围与设计选择

- SIMT32：每个 warp 的逻辑宽度为32线程；每条指令对选中线程分别执行一次32位标量操作。没有每线程 SIMD4。
- 每线程使用32位统一逻辑寄存器，整数和 FP32 共享同一位模式；不设置独立 SGPR/FPR 文件。8位寄存器字段使每线程最多可寻址256个逻辑寄存器编号（含恒零的r0），不要求固定分配256个寄存器；实际可用数量受寄存器文件及其他硬件资源限制，见 §2.1。
- 指令固定64位、小端存储、8字节对齐，直接使用8位寄存器编号，无扩展前缀。
- 采用独立的机器码、寄存器命名、控制指令及启动约定。整数采用32位二进制补码，浮点采用 IEEE 754 binary32。
- v0.1 包含整数、FP32、全局访存、分支、线程退出、warp 屏障、状态访问和 CSR 读改写。纹理、共享内存、原子操作、跨 warp 屏障、图形导出、特权态和虚拟内存不在本版范围。
- 全部已定义的 opcode/funct 指令组合均为本版本必需指令，不设置可选执行子集；不得将有副作用的指令当作 NOP。

### 1.1 术语与记号

| 术语 / 符号 | 含义 |
| --- | --- |
| thread（线程） | 一个程序执行实例，在所属 warp 内具有0–31的线程编号 |
| warp | 由最多32个实际启动线程组成的逻辑执行组；尾 warp 可以不足32线程 |
| 执行线程组 | 某次选中的同 warp、同 PC 的可执行线程集合；不是固定的硬件容量 |
| `inst[h:l]` | 64位机器指令的闭区间位切片，宽度为 `h-l+1` |
| `r[n]` | 当前线程中编号 n 的逻辑寄存器；源操作数均读取执行前状态 |
| `u32(x)` / `i32(x)` | x 的低32位分别按无符号 / 二进制补码有符号解释 |
| `sextN(x)` | 将 N 位二进制补码扩展为32位，保持符号 |
| `zextN(x)` | 将 N 位无符号字段扩展为32位，高位补零 |
| `a`、`b`、`c` | 执行前 rs1、rs2、rs3 对应的32位位模式 |
| `pc` / `next_pc` | 当前指令字节地址 / 成功执行后的字节地址 |
| 指令编码中的 reserved / MBZ | 保留位；本版本必须为零（Must Be Zero） |

所有地址与分支偏移均以字节为单位。公式中的地址和整数写回按模 2^32 截断，除非明确要求保留宽乘积或先作范围检查。位切片和移位公式表示数学位运算，不要求实现采用某一种宿主语言的移位或溢出行为。

## 2. 架构状态

| 状态 | 作用域 | 定义 |
| --- | --- | --- |
| `r0–r255` 编号空间 | 每线程 | 最多256个可编码的32位无类型逻辑寄存器编号；r0 读零、写丢弃，其余最多255个可写；实际可用数量及资源限制见 §2.1 |
| `pc` | 每线程 | 32位字节地址，要求8字节对齐 |
| `fcsr` | 每线程 | `[4:0]` 累积异常，`[7:5]` 动态舍入模式，高位零 |
| `live_mask` | 每 warp | 尚未退出的线程；初始为启动有效掩码 |
| `launch_mask` | 每 warp | 启动时固定的有效线程集合，尾 warp 可以不足32线程 |
| 屏障等待状态 | 每 warp/线程 | 记录本轮到达线程及屏障指令 PC，详见同步章节 |
| 启动参数 | 每任务 | 入口、线程总数、参数区地址；任务线程编号从零连续排列 |

写 r0 不会取消指令本身：加载仍检查地址，浮点仍累计异常，控制指令仍改变 PC。寄存器重叠合法，所有源操作数取自本条指令执行前状态。

### 2.1 逻辑编号与执行资源

8位寄存器字段提供 r0–r255 的逻辑编号空间，即每线程最多256个可编码编号，其中 r0 恒零，最多255个可写。这是编码上限，不是每线程固定配置或分配数量，也不保证每种硬件配置都能让每个线程同时使用全部编号。

程序实际使用的寄存器数量由程序需求决定；硬件能够为其提供的数量以及同时驻留的线程/warp 数量，受寄存器文件（regfile）容量、分配粒度和其他执行资源共同约束。例如，记分牌（scoreboard）条目不足可能限制可跟踪的寄存器依赖、驻留上下文或在途操作，具体影响取决于实现。ISA 不要求记分牌条目与逻辑寄存器一一对应，也不规定这些资源的固定数量。

程序寄存器用量的声明方式、资源需求检查和资源不足时的接纳/调度策略属于软件 ABI 与执行环境约定。对已接纳的程序，实现必须保持其所用逻辑寄存器的独立状态及本文规定的读写语义，不得因资源不足而截断编号、将不同编号静默别名化或丢弃有效写入。

本 ISA 固定每个 warp 的逻辑宽度为32线程，但不规定硬件 warp 数量、同时驻留的 warp/线程数量、尾 warp 的物理资源占用或任务分批调度策略。任务线程总数与同时驻留线程数是不同概念；资源接纳与调度由执行环境负责，并须保持本文规定的线程编号、执行进度和同步语义。

### 2.2 SIMT 与分支

每线程具有独立 PC。调度器从未退出且未等待屏障的线程中选取一个 PC，将同 warp、同 PC 的可执行线程组成执行掩码。每个线程独立决定条件分支结果；再次到达相同 PC 时可以合组，但不保证必须在某处重汇合。

线程内指令按程序顺序生效；持续可执行的线程最终必须获得执行机会。不同线程之间除本版屏障规定外，无隐式锁步、先后关系或进度同步。执行掩码不作为普通可写寄存器暴露。分支本身不是同步点；不能依赖某条路径先执行。

## 3. 指令编码

64位指令记为 `inst[63:0]`。`opcode=inst[7:0]`；地址 PC 处存放 bits[7:0]，随后依次存放更高字节。

采用“主 opcode 选择指令族和格式，funct 选择具体操作及特殊字段解释”的分层编码。一个指令族可以包含多条指令；多个指令族可以复用同一种格式。格式名称参考 RISC-V 的职责划分，字段位置和宽度由本规范独立定义。

```text
读取 opcode → 确定指令族及 R/R4/I/S/B/U/J 格式
            → 读取 funct，确定具体操作及特殊字段解释
            → 按格式提取寄存器、立即数、CSR 地址等字段
            → 检查保留字段及操作约束
```

### 3.1 基础格式

所有指令固定64位，寄存器编号字段固定8位。立即数的编码位数及扩展方式与 RV32I 对应格式对齐，但字段位置由 HELO 独立定义，不采用 RISC-V 的分散立即数布局，也不兼容其机器码。

#### 3.1.1 低32位：操作码与寄存器字段

每列宽度均为8位，按机器指令从高位到低位排列。表头给出 inst 位位置，表内仅给出字段名称。

| 格式 | `[31:24]` | `[23:16]` | `[15:8]` | `[7:0]` |
| --- | --- | --- | --- | --- |
| R | rs2 | rs1 | rd | opcode |
| R4 | rs2 | rs1 | rd | opcode |
| I | funct | src（通常为 rs1） | rd | opcode |
| S | funct | rs1 | rs2 | opcode |
| B | funct / cond | rs2 | rs1 | opcode |
| U | reserved | funct | rd | opcode |
| J | reserved | funct | rd | opcode |

#### 3.1.2 高32位：寄存器、立即数与控制字段

R/R4 的高32位按字节划分：

| 格式 | `[63:56]` | `[55:48]` | `[47:40]` | `[39:32]` |
| --- | --- | --- | --- | --- |
| R | reserved | ctrl | funct | reserved |
| R4 | reserved | ctrl | funct | rs3 |

立即数格式的高32位按实际字段边界划分：

| 格式 | 立即数字段位置 | 字段宽度 | 存入的位模式 | 高位保留区域 | 保留宽度 |
| --- | --- | ---: | --- | --- | ---: |
| I | `[43:32]` | 12 | imm12[11:0]；CSR 指令解释为 csr12 | `[63:44]` | 20 |
| S | `[43:32]` | 12 | imm12[11:0] | `[63:44]` | 20 |
| B | `[43:32]` | 12 | offset13[12:1] | `[63:44]` | 20 |
| U | `[51:32]` | 20 | imm20[19:0] | `[63:52]` | 12 |
| J | `[51:32]` | 20 | offset21[20:1] | `[63:52]` | 12 |

U/J 在低32位中另有 `[31:24]` 共8位保留位。所有表格合起来完整覆盖64位，字段没有重叠；立即数的符号扩展发生在解码之后，不写入保留区域。

CSR 指令是 I 型的特殊用法，不构成独立格式。I 型的8位源槽记为 src=inst[23:16]：普通指令和寄存器形式 CSR 将其解释为 rs1；立即数形式 CSR 将低5位解释为 zimm，高3位必须零，不读取源 GPR。CSR 的12位字段解释为无符号 CSR 地址，不是算术立即数。完整对照见 §3.1.5。

#### 3.1.3 立即数重建与取值范围

| 格式/用途 | 实际编码位数 | 解码后的立即数语义 |
| --- | --- | --- |
| I/S 算术、地址偏移 | 12 | `sext12(inst[43:32])`，范围 −2048 至 2047 |
| I 移位 | 12 | 低5位为移位量0–31，其余7位必须零 |
| I 陷阱编号 | 12 | `zext12(inst[43:32])`，范围0–4095 |
| I 型 CSR 地址 | 12 | `zext12(inst[43:32])`，范围0–4095；不是算术立即数 |
| I 型 CSR 立即数源 | 5 | `zext5(inst[20:16])`，范围0–31；inst[23:21] 必须零 |
| B | 12 | `offset13 = sext13(inst[43:32] << 1)`，字节偏移 −4096 至 4094，步长2 |
| U | 20 | `upper32 = inst[51:32] << 12`，结果低12位为零 |
| J | 20 | `offset21 = sext21(inst[51:32] << 1)`，字节偏移 −1048576 至 1048574，步长2 |

B/J 的最低位隐含为零；实际采用的目标仍须满足 HELO 的8字节对齐要求，不因偏移编码步长为2而允许非8字节对齐取指。汇编使用字节偏移，编码器必须检查范围及偶数要求，不得截断溢出值；取指和跳转的运行时对齐检查见第7章。

I/S/B 的高20位、U/J 的高12位暂留给未来控制字段；本版均为 reserved，必须零，不定义额外控制语义。R/R4 的 ctrl 位置及舍入用途保持独立，不能把其位位置套用到其他格式。

立即数宽度参考：[RISC-V RV32I §Immediate Encoding Variants](https://docs.riscv.org/reference/isa/v20240411/unpriv/rv32.html)。

#### 3.1.4 格式职责与字段合法性

| 格式 | 用途 |
| --- | --- |
| R | 一源或两源寄存器运算，包括整数、乘除及普通 FP32 |
| R4 | 三源寄存器运算，包括融合乘加 |
| I | 寄存器加立即数运算、加载、寄存器间接跳转，以及 CSR 读改写、退出、同步和陷阱 |
| S | 存储：rs1 为地址基址，rs2 为数据源，没有 rd |
| B | 双寄存器条件分支，立即数为相对当前 PC 的有符号字节偏移 |
| U | 高20位常量或 PC 相对地址高位构造；立即数字段左移12位 |
| J | 直接跳转并写链接地址，立即数为相对当前 PC 的有符号字节偏移 |

U/J 共享物理字段布局，但使用独立的格式语义。SYSTEM 全部使用 I 格式，funct 固定位于 inst[31:24]：0x00–0x04 为控制操作，0x07–0x09 为寄存器形式 CSR，0x0a–0x0c 为立即数形式 CSR；其他 funct 非法。funct 只选择操作及字段解释，不增加指令格式。所有真实 GPR 编号均为8位，CSR 立即数源 zimm 为5位。

- 每种格式的 reserved 字段必须零。未使用的源、目的和立即数字段必须零。
- R/R4 的 ctrl 仅在需要舍入的浮点操作中使用；其余指令 ctrl 必须零。funct 与 ctrl 是不同字段，不能以舍入模式区分 opcode。
- B 的 funct 同时作为 cond，不另设条件字段；有效值见控制流章节。
- 所有未分配的 opcode 或 opcode/funct 组合、非法 ctrl、非零保留字段均报告非法指令。
- 保留字段不得自行解释成额外寄存器或立即数；新功能必须先分配明确的编码和语义。

#### 3.1.5 I 型中 CSR 指令的特殊字段解释

下表三行均为 **I 型**，只表示不同用途，从高位到低位完整列出64位。CSR 指令不使用 ctrl 字段。

| I 型用途 | `[63:44]`（20位） | `[43:32]`（12位） | `[31:24]`（8位） | `[23:21]`（3位） | `[20:16]`（5位） | `[15:8]`（8位） | `[7:0]`（8位） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 普通操作 | reserved=0 | imm12 | funct | rs1[7:5] | rs1[4:0] | rd | opcode |
| CSR 寄存器操作 | reserved=0 | csr12 | funct | rs1[7:5] | rs1[4:0] | rd | 0x0c |
| CSR 立即数操作 | reserved=0 | csr12 | funct | reserved=0 | zimm[4:0] | rd | 0x0c |

| 字段解释 | 普通 I 型操作 | CSR 寄存器操作 | CSR 立即数操作 |
| --- | --- | --- | --- |
| 12位字段用途 | 算术/地址立即数，或 TRAP 诊断编号 | CSR 地址 | CSR 地址 |
| 12位字段扩展 | 算术/地址符号扩展；TRAP 零扩展 | 零扩展，不参与地址加法 | 零扩展，不参与地址加法 |
| 源操作数 | 通常为 GPR rs1；控制操作要求未用字段零 | 8位 GPR rs1 的旧值 | 5位数据 zimm，零扩展为32位 |
| 是否读取源 GPR | 按具体指令定义 | 是，r0 读零 | 否 |
| rd 结果 | 算术/加载结果、链接地址或未使用 | 未抑制读取时返回旧 CSR 值 | 未抑制读取时返回旧 CSR 值 |
| 特有检查 | 按指令检查移位量等 | CSR 地址、读写抑制及权限 | CSR 地址、读写抑制、权限及 inst[23:21]=0 |

CSR 立即数操作中 zimm=31 表示数据值31，不表示读取 r31；即使 r31 保存其他值，操作也不受影响。csr12=0xfff 始终表示 CSR 地址4095，不是−1偏移；本版未定义该地址，访问时报告非法状态访问。字段范围合法不等于 CSR 地址已实现。

### 3.2 主 opcode 分配

主 opcode 从 `0x01` 开始分配，选择指令族和格式；具体操作及特殊字段解释由 funct 进一步选择。`0x00` 专门保留为非法编码，使全零指令字不能作为有效程序指令执行。

| Opcode | 指令族 | 格式 | 功能 | 已定义 funct 数量 |
| --- | --- | --- | --- | ---: |
| 0x01 | OP | R | 整数寄存器运算 | 11 |
| 0x02 | OP_IMM | I | 整数立即数运算 | 9 |
| 0x03 | MULDIV | R | 整数乘除与余数 | 8 |
| 0x04 | LOAD | I | 全局内存加载 | 5 |
| 0x05 | STORE | S | 全局内存存储 | 3 |
| 0x06 | FP | R | FP32 算术、比较、分类及转换 | 18 |
| 0x07 | FMA | R4 | FP32 融合乘加 | 4 |
| 0x08 | BRANCH | B | 条件分支 | 6 |
| 0x09 | JUMP | J | PC 相对跳转并链接 | 1 |
| 0x0a | JUMP_REG | I | 寄存器间接跳转并链接 | 1 |
| 0x0b | UPPER | U | 高位常量及 PC 相对地址构造 | 2 |
| 0x0c | SYSTEM | I | CSR 读改写、退出、同步和陷阱 | 11 |

### 3.4 扩展容量与兼容规则

- 每个已定义指令族具有256个 funct 位置；新增同类运算优先分配该族的保留 funct，保持字段解析规则不变。例如 ADD 和 SUB 共享 OP/R，后续整数运算可继续加入 OP/R。
- 需要不同操作数字段的功能必须明确指定格式；可以分配新的主 opcode，也可以在已有指令族中分配 funct。例如三源运算使用 R4，存储使用 S；同一 opcode 的格式和物理字段位置保持固定；funct 可以明确指定已有字段的特殊解释，例如 I 型 CSR 的 csr12 和 zimm，但不得静默改变字段位置。
- 各格式均保留字段供未来版本使用，但本版必须检查为零。未来分配保留字段或指令时须明确版本/扩展标识，旧版本执行未知编码必须报错。
- 后续扩展不得重定义本规范定稿后已有合法编码的含义。格式数量不是指令数量，格式只约定字段布局；指令容量来自 opcode 与 funct 的组合。

## 4. 整数语义

令 a、b、c 为执行前 rs1、rs2、rs3 的32位位模式，u32 表示无符号解释，i32 表示二进制补码有符号解释。所有写回结果均截断到32位；整数溢出不陷阱、不修改 fcsr。

### 4.1 数据移动与高位构造

| 指令 | 写回 rd | 说明 |
| --- | --- | --- |
| MOV | a | 原样复制位模式，不作数值转换 |
| MOVI | `imm20 << 12` | 高20位来自字段，低12位清零 |
| LEAPC | `u32(pc + (imm20 << 12))` | 基准是当前指令 PC |

MOVI/LEAPC 的汇编操作数为20位字段值（0–0xfffff），不是已左移的32位值。MOVI 是一条 U 型真实指令，不是装载任意32位常量的伪指令。任意32位常量的两指令构造见 §10.4。

### 4.2 整数寄存器运算

| 指令 | 写回 rd | 边界约定 |
| --- | --- | --- |
| ADD | `u32(a + b)` | 忽略超出32位的进位 |
| SUB | `u32(a - b)` | 忽略超出32位的借位 |
| AND | a 与 b 按位与 | 不更新条件码 |
| OR | a 与 b 按位或 | 不更新条件码 |
| XOR | a 与 b 按位异或 | 不更新条件码 |
| SHL | `u32(a << (b & 31))` | 低位补零 |
| SHR | a 逻辑右移 `b & 31` 位 | 高位补零 |
| SAR | a 算术右移 `b & 31` 位 | 高位复制 a 的符号位 |
| SLT | `i32(a) < i32(b)` 时为1，否则0 | 有符号比较 |
| SLTU | `u32(a) < u32(b)` 时为1，否则0 | 无符号比较 |

### 4.3 整数立即数运算

令 `k = sext12(imm12)`。逻辑立即数也必须符号扩展；指令名中的 U 只改变比较方式，不改变扩展方式。

| 指令 | 对应操作 | 立即数规则 |
| --- | --- | --- |
| ADDI | ADD，以 k 替代 b | 12位有符号立即数 |
| ANDI | AND，以 k 替代 b | k 的完整32位参与按位与 |
| ORI | OR，以 k 替代 b | k 的完整32位参与按位或 |
| XORI | XOR，以 k 替代 b | k 的完整32位参与按位异或 |
| SLTI | `i32(a) < i32(k)` 时为1，否则0 | 有符号比较 |
| SLTIU | `u32(a) < u32(k)` 时为1，否则0 | 先符号扩展，再无符号比较 |
| SHLI | SHL，移位量来自 imm12[4:0] | imm12[11:5] 必须零 |
| SHRI | SHR，移位量来自 imm12[4:0] | imm12[11:5] 必须零 |
| SARI | SAR，移位量来自 imm12[4:0] | imm12[11:5] 必须零 |

例如 `XORI rd, rs1, -1` 对 a 的32位全部取反；`SLTIU rd, rs1, -1` 将 a 与 0xffffffff 作无符号比较。寄存器移位取源值低5位，立即数移位则拒绝超出0–31的编码，两者不能混淆。

### 4.4 乘法、除法与余数

| 指令 | 操作数解释 | 写回 rd |
| --- | --- | --- |
| MUL | 32位乘法；低半部与符号解释无关 | 完整乘积低32位 |
| MULH | 有符号 a × 有符号 b | 64位二进制补码乘积高32位 |
| MULHSU | 有符号 a × 无符号 b | 64位二进制补码乘积高32位 |
| MULHU | 无符号 a × 无符号 b | 64位乘积高32位 |
| DIV | 有符号 a / b | 商向零截断 |
| DIVU | 无符号 a / b | 无符号商 |
| REM | 有符号 a / b | 余数非零时与被除数同号 |
| REMU | 无符号 a / b | 无符号余数 |

正常有符号除法满足 `a = 商 × b + 余数`。下表异常输入产生确定结果，不产生整数陷阱，也不修改 fcsr。

| 输入条件 | DIV | DIVU | REM | REMU |
| --- | --- | --- | --- | --- |
| b = 0 | 0xffffffff | 0xffffffff | a | a |
| a = 0x80000000，b = 0xffffffff | 0x80000000 | 0 | 0 | 0x80000000 |

第二行只有有符号除法发生溢出；DIVU/REMU 对相同位模式执行普通无符号运算。

## 5. FP32 语义

所有 F 指令操作 IEEE 754 binary32 位模式，没有隐式整数转换。FCVT 名称按“目的类型_源类型”排列。MOV/LD32/ST32 可直接传输浮点位模式，包括 NaN payload。

### 5.1 舍入与状态

ctrl 是 R/R4 中位于 inst[55:48] 的8位控制字段；它不是新的 opcode。

需要舍入的指令使用 `ctrl[2:0]`，`ctrl[7:3]` 必须零；不需要舍入的指令要求整个 ctrl 为零。

| rm | 含义 |
| --- | --- |
| 0 | RNE：最近，正好中间取偶数 |
| 1 | RTZ：向零 |
| 2 | RDN：向负无穷 |
| 3 | RUP：向正无穷 |
| 4 | RMM：最近，正好中间取绝对值较大者 |
| 5、6 | 非法 |
| 7 | DYN：使用本线程 fcsr.frm |

动态 frm 为5–7时，仅执行需要舍入的动态指令才报告非法舍入模式。fcsr 写入允许保存这些位模式；非舍入指令不因 frm 无效失败。

`fflags[4:0]={NV,DZ,OF,UF,NX}`，分别表示无效操作、除零、上溢、下溢、不精确。新标志与旧标志按位 OR，不触发浮点陷阱。支持次正规输入/输出，不启用 flush-to-zero；微小性在舍入后、按目标精度和无界指数范围的舍入值判断。

| fcsr 位 | 状态名 | 定义 |
| --- | --- | --- |
| 0 | NX | 结果不精确 |
| 1 | UF | 下溢 |
| 2 | OF | 上溢 |
| 3 | DZ | 除零 |
| 4 | NV | 无效操作 |
| [7:5] | FRM | 动态舍入模式 |
| [31:8] | reserved | 读零；状态写入时忽略 |

指令编码的保留位要求零，而 FCSR 写入的高位按状态访问规则忽略；这两种规则属于不同接口。

| 操作组 | 使用 ctrl.rm | 可能更新异常标志 |
| --- | --- | --- |
| FADD/FSUB/FMUL/FDIV/FSQRT、四种 FMA、四种 FCVT | 是 | 是，按操作结果累计 |
| FMIN/FMAX、FEQ/FLT/FLE | 否，ctrl=0 | 是，按 NaN 规则累计 NV |
| FSGNJ/FSGNJN/FSGNJX、FCLASS | 否，ctrl=0 | 否 |

### 5.2 运算与特殊值

- FADD/FSUB/FMUL/FDIV/FSQRT 分别为加、减、乘、除、平方根，按指定模式舍入。
- FMADD=a×b+c；FMSUB=a×b−c；FNMSUB=−(a×b)+c；FNMADD=−(a×b)−c。乘加整体只舍入一次，符号零及特殊值遵循上述融合操作的 IEEE 语义。
- 算术 NaN 结果统一为 0x7fc00000；signaling NaN 设置 NV。异常组合（例如无穷乘零、零除零）遵循 IEEE 运算语义。
- FSGNJ 保留 a 的低31位，符号取 b；FSGNJN 符号取反 b；FSGNJX 符号为 a 与 b 符号异或。保留 payload，不设置任何异常。
- FMIN/FMAX：一个操作数为 NaN 时返回另一个；两个都是 NaN 时返回规范 NaN；任一 signaling NaN 设置 NV。负零小于正零。
- FEQ/FLT/FLE 返回整数0或1；任何 NaN 比较均返回0。FEQ 仅 signaling NaN 设置 NV；FLT/FLE 对任意 NaN 设置 NV。正负零比较相等。
- FCLASS 返回十位 one-hot 位图：bit0负无穷、1负正常数、2负次正规数、3负零、4正零、5正次正规数、6正正常数、7正无穷、8 signaling NaN、9 quiet NaN；高位零，不设置异常。
- FCVT_F32_I32/U32 将相应整数转换为 FP32。FCVT_I32/U32_F32 按指定模式舍入后转整数；超范围或 NaN 设置 NV，返回下表饱和值。转换无效时不额外设置 NX；其他不精确转换设置 NX。

| 浮点转整数无效情况 | I32 结果 | U32 结果 |
| --- | --- | --- |
| 负向越界（包括负无穷） | 0x80000000 | 0 |
| 正向越界（包括正无穷） | 0x7fffffff | 0xffffffff |
| NaN | 0x7fffffff | 0xffffffff |

浮点转整数的越界以舍入后的数学整数判定；例如负的小数向零舍入得到0时，可以是有效的 U32 转换。

### 5.3 FCLASS 分类位

FCLASS 的结果只有下表对应的一位为1；bits[31:10] 必须零。当指数位全1且尾数非零时，尾数最高位 bit22=1 表示 quiet NaN，bit22=0 表示 signaling NaN；分类不改变源数据。

| 结果位 | 类别 |
| ---: | --- |
| 0 | 负无穷 |
| 1 | 负正常数 |
| 2 | 负次正规数 |
| 3 | 负零 |
| 4 | 正零 |
| 5 | 正次正规数 |
| 6 | 正正常数 |
| 7 | 正无穷 |
| 8 | signaling NaN |
| 9 | quiet NaN |

## 6. 存储模型

### 6.1 地址与数据访问

- 使用32位统一字节地址、最多4 GiB，小端；实现可以只映射其中一部分，未映射地址访问报错。
- LD/ST 地址为 `u32(r[rs1] + sext12(imm12))`。地址加法按模2^32，但单次多字节访问不能跨越地址空间末端并回绕。
- LD8/LD16 分别符号扩展8/16位到32位，LD8U/LD16U 零扩展；LD32 原样读取32位。
- ST8/ST16/ST32 写 S 格式 rs2 指定源寄存器的低8/16/32位，无寄存器写回。汇编写作 `ST32 rData, [rBase + offset]`。
- 所有数据访问要求自然对齐：1/2/4字节。取指要求8字节对齐，并且完整8字节均可访问。

| 指令 | 访问字节数 | 地址对齐 | 加载结果 / 存储数据 |
| --- | ---: | ---: | --- |
| LD8 | 1 | 1 | 8位符号扩展到32位 |
| LD8U | 1 | 1 | 8位零扩展到32位 |
| LD16 | 2 | 2 | 16位符号扩展到32位 |
| LD16U | 2 | 2 | 16位零扩展到32位 |
| LD32 | 4 | 4 | 原样读取32位 |
| ST8 | 1 | 1 | 写入 rs2 的低8位 |
| ST16 | 2 | 2 | 写入 rs2 的低16位 |
| ST32 | 4 | 4 | 写入 rs2 的全部32位 |

访问 N 字节时，必须检查完整区间 `[address, address+N-1]`；范围检查采用足够宽的算术，不能先回绕末地址。小端存储下，最低地址对应值的最低8位。例如 ST32 存储 0x12345678，内存中四字节依次为 `78 56 34 12`。

### 6.2 内存顺序与可见性

- 本版对普通、无副作用内存定义每线程访存按程序顺序、所有线程访存存在一个保持线程内顺序的全序；每次自然对齐加载/存储是不可撕裂的单次访问。不定义 MMIO。不同线程存在数据竞争时，具体全序不确定，软件不得依赖线程编号决定竞争结果。
- FENCE 等待当前参与线程此前的访存完成后才继续，但不等待其他线程，不是屏障。
- BARW 为指定的 warp 内线程建立同步和内存可见性，见下节；本版没有跨 warp 通信的同步指令。
- 执行期间禁止修改当前任务的指令字节。主机只能在任务启动前加载程序、任务完成或停止后读取结果；不定义并发主机访问和自修改代码。
- 缓存组织、带宽和延迟不属于 ISA；实现必须保证本章规定的内存顺序及可见性。

| 操作 | 等待其他线程 | 作用范围与保证 |
| --- | --- | --- |
| 普通 LD/ST | 否 | 保持本线程程序顺序，并遵守上文全序要求 |
| FENCE | 否 | 等待当前参与线程自己的先前访存完成 |
| BARW | 是 | 固定 launch_mask 内到达与访存完成；建立屏障前后可见性 |

普通 LD/ST 的不可撕裂性不等于原子读改写。例如两个线程分别执行“加载、加一、存储”，不保证计数增加两次。本版不定义跨 warp 屏障或原子读改写指令。

## 7. 控制流与同步

普通指令完成后 `pc=u32(pc+8)`。PC 加法按模2^32；下一次取指仍进行完整范围检查。以下操作覆盖普通的 PC 更新。

| 指令 | 语义 |
| --- | --- |
| BR | 条件成立时跳到 `u32(pc+offset13)`，否则 pc+8 |
| JAL | rd 写入 pc+8，跳到 `u32(pc+offset21)` |
| JALR | rd 写入 pc+8，跳到 `u32(old_r[rs1]+sext12(imm12))`；不清除任何低位 |
| EXIT | 当前参与线程退出，清除相应 live 位，不再取指 |
| TRAP | 报告显式陷阱，携带零扩展的12位 imm12 诊断编号（0–4095） |
| BARW | warp 内固定参与集合的可重复使用屏障 |

**分支条件编码**

| funct / cond | 汇编后缀 | 条件 | 解释 |
| --- | --- | --- | --- |
| 0x00 | EQ | a = b | 位模式相等 |
| 0x01 | NE | a ≠ b | 位模式不等 |
| 0x02 | LT | i32(a) < i32(b) | 有符号小于 |
| 0x03 | GE | i32(a) ≥ i32(b) | 有符号大于等于 |
| 0x04 | LTU | u32(a) < u32(b) | 无符号小于 |
| 0x05 | GEU | u32(a) ≥ u32(b) | 无符号大于等于 |
| 0x06–0xff | — | 非法 | 不得执行为其他条件 |

比较对象均为32位寄存器。只有实际采用的跳转目标需要满足8字节对齐；失败时不写链接寄存器。目标是否映射在下一次取指检查。`JAL r0, offset` 是无条件跳转；`JALR r0, rLink, 0` 是返回，无专用调用栈。

B/J 可编码的偏移包含2字节倍数；从8字节对齐 PC 出发，合法的已采用分支偏移还必须是8的倍数。因此 BR 的可执行偏移范围为 −4096 至 4088，JAL 为 −1048576 至 1048568。BR 未采用路径的目标无需检查对齐；非法 funct 和保留位仍必须检查。

当 JALR 的 rd 与 rs1 相同时，先用旧 rs1 计算目标，再写入链接值 `u32(pc+8)`。HELO 的 JALR 不执行 RISC-V 的最低位清零操作；本 ISA 也没有分支延迟槽。

### 7.1 BARW 协议

- 参与者固定为 launch_mask，尾 warp 只等待真实启动线程。每 warp 同时最多一轮未完成屏障。
- 线程到达 BARW 后登记到达并暂停，PC 保持在该指令处。第一次到达记录屏障 PC；同一轮所有参与者必须到达相同 PC。
- 全部参与者到达且其此前访存完成后，一起解除等待、PC 加8并清除本轮到达状态。屏障前任一参与者的存储对屏障后其他参与者的加载可见。
- 下一轮可重用同一 PC，也可以使用另一个 BARW PC；到达状态每轮重新累计。
- 已有线程 EXIT 后再执行 BARW，或未完成屏障期间有其他线程 EXIT，报告屏障协议错误。到达不同 BARW PC 同样报错。
- 某个线程无限循环而不到达屏障属于程序无进展；执行环境可以暂停任务，但超时或执行预算耗尽不属于 ISA 陷阱。

**屏障状态转换**

| 当前状态 / 事件 | 结果 |
| --- | --- |
| 无未完成轮次，第一个参与者到达 PC=P | 记录 P 和到达位，线程等待 |
| 本轮未完成，其他参与者到达同一 P | 合并到达位，尚未释放的线程继续等待 |
| 全部参与者到达，但先前访存未全部完成 | 保持等待 |
| 全部参与者到达且先前访存全部完成 | 统一解除等待，各线程 PC=P+8，清除本轮状态 |
| 本轮参与者到达另一 BARW PC | 屏障协议错误 |
| 已退出线程存在时再执行 BARW，或等待期间出现 EXIT | 屏障协议错误 |

“统一解除等待”不要求线程在同一物理周期继续执行。循环可以多次执行同一静态 BARW；每次释放开始新的动态轮次。程序必须保证固定参与集合中的线程按相容顺序执行这些屏障，不能依赖退出线程自动减少参与集合。

## 8. 状态访问与最小启动约定

### 8.1 CSR 地址空间与状态访问

架构状态统一映射到 HELO 的12位 CSR 地址空间（0–4095），只通过 CSRRW、CSRRS、CSRRC、CSRRWI、CSRRSI、CSRRCI 六条机器指令访问。所有 CSR 值以32位读取；访问未定义地址或实际写入只读 CSR 报告非法状态访问。

下表地址沿用 HELO 定义，其中 FFLAGS=0x000、FRM=0x001、FCSR=0x002，不采用 RISC-V 的0x001/0x002/0x003编号。读写权限由下表定义，不从地址高位推导特权级或只读属性。未列出的地址非法；本版没有特权态，也没有读清除、写触发 I/O 等 CSR 副作用。

| 编号 | 名称 | 权限 | 值 |
| --- | --- | --- | --- |
| 0x000 | FFLAGS | 读写 | 低5位异常标志；写替换，其他位忽略 |
| 0x001 | FRM | 读写 | 低3位舍入模式；写替换，其他位忽略 |
| 0x002 | FCSR | 读写 | 低8位组合状态；高位读零、写忽略 |
| 0x010 | WARP_THREAD_ID | 只读 | warp 内线程编号0–31 |
| 0x011 | WARP_ID | 只读 | 本任务 warp 序号，从零开始 |
| 0x012 | GLOBAL_THREAD_ID | 只读 | WARP_ID×32+WARP_THREAD_ID |
| 0x013 | THREAD_COUNT | 只读 | 任务实际启动线程总数 |
| 0x014 | WARP_SIZE | 只读 | 恒32 |
| 0x015 | PARAM_BASE | 只读 | 主机提供的32位参数区地址 |
| 0x016 | ISA_VERSION | 只读 | v0.1 返回 0x00000001；主版本在高16位、次版本在低16位 |

FFLAGS/FRM 更新不改变 FCSR 的另一部分。状态访问按本线程指令顺序，与前后浮点指令保持依赖顺序。GLOBAL_THREAD_ID 等值不受执行掩码分组影响。

### 8.2 CSR 读改写指令

#### 8.2.1 编码与值变换

六条 CSR 指令属于 SYSTEM（opcode=0x0c），全部使用 I 格式，其特殊字段解释见 §3.1.5。csr12=inst[43:32] 始终是 CSR 无符号地址；寄存器形式从旧 r[rs1] 取值，立即数形式从 inst[20:16] 取 zimm5。所有形式的 inst[63:44] 必须零，立即数形式还要求 inst[23:21] 为零。

| 指令 | funct | 源值 v | 写入候选值 |
| --- | --- | --- | --- |
| CSRRW | 0x07 | 旧 r[rs1] | v |
| CSRRS | 0x08 | 旧 r[rs1] | old 按位 OR v |
| CSRRC | 0x09 | 旧 r[rs1] | old 按位 AND u32(NOT v) |
| CSRRWI | 0x0a | zext5(zimm) | v |
| CSRRSI | 0x0b | zext5(zimm) | old 按位 OR v |
| CSRRCI | 0x0c | zext5(zimm) | old 按位 AND u32(NOT v) |

old 是本条指令之前的 CSR 可见值。发生 CSR 读取且 rd≠r0 时，将 old 写回 rd；发生 CSR 写入时，先检查权限，再按 §8.1 的有效位规则保存候选值。写 FFLAGS/FRM 只修改 FCSR 的对应部分；写 FCSR 同时替换其低8位。高位写忽略不等于只读 CSR 可以被写入。

#### 8.2.2 读写抑制

| 指令 | CSR 读取 | CSR 写入 | 关键判定 |
| --- | --- | --- | --- |
| CSRRW / CSRRWI | rd≠r0 时发生 | 始终发生 | rd=r0 仅抑制读取 |
| CSRRS / CSRRC | 始终发生 | rs1≠r0 时发生 | 判断寄存器编号，不判断寄存器保存的值 |
| CSRRSI / CSRRCI | 始终发生 | zimm≠0 时发生 | 判断立即数字段的值 |

`CSRRW rd, csr, r0` 写入零；`CSRRWI rd, csr, 0` 也写入零。`CSRRS rd, csr, r0` 和 `CSRRC rd, csr, r0` 只读。若 rs1 是非零编号但其中保存零，CSRRS/CSRRC 仍然属于写访问，访问只读 CSR 必须失败。CSRRS[I]/CSRRC[I] 的 rd=r0 只丢弃读出的值，不抑制 CSR 读取。

CSR 地址合法性始终检查。对只读 CSR，只有实际发生写入时才报告非法状态访问；对不存在的 CSR，即使读写值均不被程序使用也必须报错。失败时不能先改写 rd 或 CSR。CSRRWI 的 zimm 即使为零，仍属于写操作。

**只读 CSR 的访问判定示例（csr=GLOBAL_THREAD_ID）**

| 指令 | 源值条件 | 是否合法 | 原因 |
| --- | --- | --- | --- |
| CSRRW r0, csr, r0 | 固定零 | 否 | 仍然写零 |
| CSRRS r1, csr, r0 | 固定零 | 是 | 只读 |
| CSRRC r0, csr, r2 | r2 中为零 | 否 | 非零源编号仍产生写访问 |
| CSRRWI r0, csr, 0 | zimm=0 | 否 | 始终写入 |
| CSRRSI r1, csr, 0 | zimm=0 | 是 | 写入被抑制 |
| CSRRCI r0, csr, 1 | zimm=1 | 否 | 产生清位写入 |

#### 8.2.3 顺序与作用域

单条 CSR 指令对当前线程的 CSR 访问是不可分割的读改写；与同线程先前/后续浮点指令及其他 CSR 指令按程序顺序生效。FCSR、FRM、FFLAGS 是同一状态的不同视图，其隐式和显式依赖必须一并保持。rd=rs1 时，先捕获旧 GPR 值，再进行读改写和写回。

这里的原子性仅指单线程 CSR 操作；不建立跨线程通信，不提供全局内存原子操作或内存屏障。每个参与线程独立访问自己的浮点状态；任务参数等只读 CSR 读取各自规定的值。本章不为 CSR 指令增加内存排序能力。

#### 8.2.4 汇编别名与用例

下列别名仅是汇编简写，不占用额外 opcode/funct。

| 别名 | 单条真实指令展开 |
| --- | --- |
| CSRR rd, csr | CSRRS rd, csr, r0 |
| CSRW csr, rs1 | CSRRW r0, csr, rs1 |
| CSRS csr, rs1 | CSRRS r0, csr, rs1 |
| CSRC csr, rs1 | CSRRC r0, csr, rs1 |
| CSRWI csr, zimm | CSRRWI r0, csr, zimm |
| CSRSI csr, zimm | CSRRSI r0, csr, zimm |
| CSRCI csr, zimm | CSRRCI r0, csr, zimm |

```text
CSRRS  r1, 0x012, r0      ; 读取 GLOBAL_THREAD_ID，合法只读访问
CSRRWI r2, 0x001, 1       ; 保存旧 FRM 到 r2，并设置 RTZ
CSRRCI r3, 0x000, 31      ; 保存旧 FFLAGS 到 r3，并清除全部5位
CSRRW  r0, 0x001, r2      ; 恢复 FRM，不读取旧 FRM
```

CSRRCI 的5位源足以清除 FFLAGS，但不能直接选择 FCSR 的 bit5–7；修改 FRM 可访问0x001，修改完整 FCSR 可使用寄存器形式。地址与数据立即数不可交换。

### 8.3 启动参数与初始状态

| 参数 | 宽度 | 含义 |
| --- | ---: | --- |
| entry_pc | 32位 | 程序入口字节地址，要求8字节对齐 |
| thread_count | 32位无符号 | 整个任务的实际线程总数，不表示驻留容量 |
| param_base | 32位 | 参数区字节地址，启动时不自动解引用 |

任务启动参数为 `(entry_pc, thread_count, param_base)`，thread_count 表示任务线程总数，必须能用32位无符号值表示，不表示同时驻留线程数；资源接纳约定见 §2.1。入口必须8字节对齐且可完整取指；零线程任务可立即完成，仍须检查入口对齐但无需实际取指。param_base 不在启动时自动解引用。每个实际线程开始执行时初始 PC=entry_pc、程序所用的可写逻辑 GPR=0、FCSR=0，无隐式线程编号 GPR；该初值约定不要求为未使用编号预留或清零物理存储。全部任务线程 EXIT 后任务完成；任务启动/退出不是 CPU 系统调用。

对任务内全局线程编号 `t`（GLOBAL_THREAD_ID），逻辑映射为 `warp_id = floor(t/32)`、`warp_thread_id = t mod 32`。每个 warp 的 launch_mask 仅包含 t 小于 thread_count 的实际线程；其初始 live_mask 等于 launch_mask。例如 thread_count=35 时，第0个 warp 的 launch_mask 为 0xffffffff，第1个为 0x00000007。此例描述逻辑编号，不要求两个 warp 同时驻留。

| 架构状态 | 每个实际线程 / warp 的初值 |
| --- | --- |
| pc | entry_pc |
| 程序所用可写逻辑寄存器 | 0 |
| fcsr | 0（fflags=0，frm=RNE） |
| launch_mask / live_mask | 实际启动线程掩码 |
| BARW 等待状态 | 无未完成轮次，无已登记到达者 |

### 8.4 软件 ABI 边界

程序通过 `CSRRS rd, csr12, r0` 获取线程编号和参数区地址，再用 LD32 等读取参数。本版不规定栈寄存器、被调用者保存寄存器、函数参数寄存器、链接器重定位或可执行文件格式。这些约定属于独立的软件 ABI，不能改变本文规定的指令语义。

### 8.5 功能模型图形调用约定

[图形Shader ABI](graphics_abi.md) 定义独立的顶点/片元寄存器 ABI。
当前GPU内部Cp先调用普通Shader launch 完成上述零初始化，再通过功能模型的
显式寄存器访问接口写入图形输入，最后才执行机器码。这是执行环境准备
上下文的操作，不是 v0.1 新增的装载、图形导出或纹理采样指令，也不改变
普通计算任务的零初始化规则。仅按本 ISA 启动计算程序时，不能假设存在
图形输入寄存器。

图形任务分批后，CSR 的线程编号和线程总数对应当前 Shader launch；
图形全局编号、阶段输出、片元丢弃以及固定功能采样均以图形 ABI 文档为准。
此次图形集成没有占用新的 opcode/funct 或提升 ISA 版本。

## 9. 错误与提交边界

### 9.1 错误类别

| 错误 | 触发条件示例 |
| --- | --- |
| 非法编码 | opcode=0、未分配 opcode/funct、非零保留位、非法静态 rm、移位高位非零、CSR 立即数源 inst[23:21] 非零 |
| 非法状态访问 | 状态/CSR 地址不存在，或 CSR 指令实际写入只读状态 |
| 非法动态舍入 | rm=DYN，当前线程 frm 为5–7 |
| 未对齐访问 / 跳转 | 取指、数据地址或已采用跳转目标不满足对应对齐 |
| 访问越界 | 完整访问区间未映射或跨越32位地址空间末端 |
| 显式陷阱 | 执行 TRAP，诊断编号取其12位立即数 |
| 屏障协议错误 | BARW 到达位置不一致，或 EXIT 违反固定参与集合要求 |

### 9.2 提交与诊断

- 执行同 PC 线程组时，必须先验证所有参与线程的当前指令，再提交其 GPR、浮点状态、数据存储和 PC/退出变化。任一线程失败，该次指令组不产生部分架构副作用；此前完成的其他指令不回滚。
- 取指失败时尚未解码，无该条指令副作用。BARW 到达登记作为成功执行动作提交；随后发现协议错误不会回滚已成功登记的其他线程。
- 任务遇到错误停止执行并锁存诊断；本版不支持程序内陷阱处理或故障恢复。诊断至少提供错误类型、warp、线程或线程掩码、PC，取到机器码时还应提供机器码。
- 上述失败提交边界不提供跨线程普通数据访问的事务隔离保证；错误诊断以实际选中的执行线程组为单位。
- 执行环境暂停任务后可从原状态继续；任务复位或重新启动清除上下文和锁存错误，不隐式清除外部内存。

## 10. 编码及程序示例

### 10.1 汇编操作数约定

| 操作数类别 | 汇编表示与范围 |
| --- | --- |
| 寄存器 | r0–r255，编号采用十进制 |
| I/S 算术或地址立即数 | 数学整数 −2048 至 2047；负值用负号表示 |
| 移位立即数 | 0–31 |
| 状态 / CSR 地址 / 陷阱编号 | 0–4095，可用十六进制表示 |
| CSR 立即数源 zimm | 0–31，零扩展；不是 GPR 编号 |
| U 型立即数 | 原始20位字段，0–0xfffff；由指令左移12位 |
| B/J 偏移 | 有符号字节偏移，范围见 §3.1.3；最低位必须零 |
| 浮点舍入 | RNE、RTZ、RDN、RUP、RMM、DYN；DYN 编码为7 |

十六进制表示不改变操作数的取值范围。例如算术操作数 −1 的12位编码为 0xfff，但本规范的汇编示例写作 `-1`；`ADDI ..., 0xfff` 不能作为正4095静默截断。

### 10.2 编码构造

汇编记法中，寄存器写作 r0–r255，立即数允许十进制或 0x 前缀十六进制；分支后缀指定 cond，浮点最后一个操作数指定舍入模式。R/R4 格式公式：

```text
inst = opcode | (rd<<8) | (rs1<<16) | (rs2<<24)
     | (rs3<<32) | (funct<<40) | (ctrl<<48)
```

R 格式公式中的 rs3 必须置零；R4 使用真实 rs3。编码时必须先将字段转成64位无符号数再移位。I/S 将12位立即数字段放入 inst[43:32]；B 将13位字节偏移的 bits[12:1] 放入 inst[43:32]；U 将20位字段放入 inst[51:32]；J 将21位字节偏移的 bits[20:1] 放入 inst[51:32]。有符号值先检查范围再取相应宽度的二进制补码；字段之外的保留位必须零，不填充符号扩展位。

其他格式的字段拼接公式如下。`payload` 是范围检查后得到的无符号编码字段：I/S 取 imm12，B 取 offset13[12:1]，U 取 imm20，J 取 offset21[20:1]。

```text
I: inst = opcode | (rd<<8)  | (src<<16) | (funct<<24) | (payload<<32)
S: inst = opcode | (rs2<<8) | (rs1<<16) | (funct<<24) | (payload<<32)
B: inst = opcode | (rs1<<8) | (rs2<<16) | (cond<<24)  | (payload<<32)
U: inst = opcode | (rd<<8)  | (funct<<16) | (payload<<32)
J: inst = opcode | (rd<<8)  | (funct<<16) | (payload<<32)
```

I 型的 CSR 用法将通用拼接公式中的 payload 解释为 csr12，将 src 解释为 rs1 或 zimm；csr12 不作符号扩展，zimm 必须在0–31之间：

```text
I (CSR register): inst = 0x0c | (rd<<8) | (rs1<<16)  | (funct<<24) | (csr12<<32)
I (CSR immediate): inst = 0x0c | (rd<<8) | (zimm<<16) | (funct<<24) | (csr12<<32)
```

## 11. 逐条指令参考

本章按基础整数、控制转移、访存、乘除、浮点、CSR 和 HELO 控制功能组织，与 RISC-V 非特权手册的功能分节方式对应。全部79个已定义 opcode/funct 组合仍各有独立条目；第3章保留按编码查找的目录。

每条先描述源操作数、计算及写回，再给出简洁的架构操作和特殊情况。正文与操作共同定义 HELO 行为。这里的伪代码是 HELO 的架构说明，不是引用的 RISC-V 原文、Sail 模型或实现代码；RISC-V 基础手册本身主要使用文字与编码图描述操作。

### 11.0 架构操作记号

| 记号 | 架构含义 |
| --- | --- |
| `R[n]` | 当前线程的32位逻辑通用寄存器；读取 R[0] 得零，写入 R[0] 被丢弃 |
| `CSR[c]` | 地址 c 的32位 CSR 视图；写入遵守有效位、别名和权限规则 |
| `M8[a]`、`M16[a]`、`M32[a]` | 从字节地址 a 开始的小端内存值；赋值表示对应宽度的存储 |
| `←` | 架构赋值或临时值绑定；R 写回保留低32位，不表示物理写回时序 |
| `a`、`b`、`c` | 旧 R[rs1]、R[rs2]、R[rs3] 的位模式；只有真实寄存器源才读取 |
| `fa`、`fb`、`fc` | 将 a、b、c 解释为 binary32，未经整数到浮点转换 |
| `u32`、`i32`、`sextN`、`zextN` | 位宽截断、有符号解释及扩展，见 §1.1 |
| `bool32(p)` | 条件 p 成立返回1，否则返回0 |
| `round32` / `round32_fused` | 按第5章返回 FP32 结果位模式和异常集合；后者整体仅舍入一次 |
| `resolve_rm` / `round_to_integer` | 选择舍入模式 / 按模式舍入为数学整数；无穷按方向超范围处理 |
| `check_data_access(a, N)` | 检查 N 字节访问的自然对齐、完整映射及地址空间边界 |
| `require` / `error` | 条件不成立或显式错误时按第9章报告异常，不提交失败指令组副作用 |

读取源操作数先于目的写入。CSR 的读写抑制由条件控制：未执行 `old ← CSR[c]` 表示不发生架构读取，而不是读取后丢弃结果。CSR 赋值应用 §8 的有效位规则；FFLAGS/FRM/FCSR 仍是同一状态的不同视图。

除条目显式指定控制流外，成功执行后 `next_pc ← u32(pc+8)`。普通算术、访存和 CSR 不修改线程掩码。每条指令均检查其格式保留位和未使用字段，不需要在每个操作块重复这些检查。

操作描述不指定流水线顺序；临时量、R、CSR、内存和 PC 的候选更新均受第9章线程组提交规则约束。BARW 到达登记和释放按其专门协议处理。异常标志累计不等于浮点陷阱，CSR 读改写不等于跨线程内存原子操作。

### 11.1 整数寄存器—立即数指令

本节描述以一个寄存器和立即数计算结果的指令，以及 U 型高位构造。立即数扩展规则见 §3.1.3。

<a id="insn-addi"></a>

#### 11.1.1 ADDI — 整数加立即数

```text
ADDI rd, rs1, simm12
```

编码：**I 型**，opcode=`0x02`，funct=`0x00`。

ADDI 先将12位立即数符号扩展为32位，再与 rs1 的值相加，结果写入 rd。加法结果保留低32位。

操作：

```text
k ← sext12(imm12)
R[rd] ← u32(a + k)
```

imm12 先符号扩展，包括逻辑指令和 SLTIU。立即数数学范围为−2048至2047；编码器不得静默截断。不修改 FCSR。

示例：`ADDI r3, r1, -1`。

<a id="insn-slti"></a>

#### 11.1.2 SLTI — 有符号立即数比较

```text
SLTI rd, rs1, simm12
```

SLTI 比较 rs1 与符号扩展后的12位立即数。比较按有符号方式进行，rs1 小于该值时向 rd 写入1，否则写入0。

操作：

```text

R[rd] ← bool32(i32(a) < i32(k))
```

imm12 先符号扩展，包括逻辑指令和 SLTIU。立即数数学范围为−2048至2047；编码器不得静默截断。不修改 FCSR。

示例：`SLTI r3, r1, -1`。

#### 11.1.7 SHLI — 立即数逻辑左移

```text
SHLI rd, rs1, shamt
```

编码：**I 型**，opcode=`0x02`，funct=`0x04`。

操作：

```text
require imm12[11:5] == 0
shamt ← imm12[4:0]
R[rd] ← u32(a << shamt)
```

shamt 范围0–31；与寄存器移位不同，立即数高7位非零必须报告非法编码。不修改 FCSR。

#### 11.1.10 MOVI — 构造高20位常量

```text
MOVI rd, imm20
```

编码：**U 型**，opcode=`0x0b`，funct=`0x00`。

MOVI 使用 U 型编码构造32位常量：将20位立即数放入 rd 的高20位，并将低12位清零。汇编中写出的操作数是未左移的20位字段值。

操作：

```text
R[rd] ← imm20 << 12
```

低12位为零；汇编参数为20位字段值，不是完整32位结果。不修改 FCSR，完整常量构造见 §10.4。

示例：`MOVI r3, 0x3f800  ; 得到 FP32 1.0 的位模式`。

<a id="insn-leapc"></a>

#### 11.1.11 LEAPC — 构造 PC 相对高位地址

```text
LEAPC rd, imm20
```

编码：**U 型**，opcode=`0x0b`，funct=`0x01`。

LEAPC 将20位立即数左移12位，与本条指令的 PC 相加，把低32位结果写入 rd。该指令只产生地址值，不改变控制流；后续指令可补入低12位偏移。

操作：

```text
R[rd] ← u32(pc + (imm20 << 12))
```

只构造数据值，不跳转、不检查结果地址映射。基准为当前 PC；可配合 ADDI 或 JALR 加入低12位偏移。

示例：`LEAPC r3, 0  ; 得到本条指令 PC`。

<a id="insn-slt"></a>

#### 11.2.3 SLT — 有符号小于比较

```text
SLT rd, rs1, rs2
```

编码：**R 型**，opcode=`0x01`，funct=`0x08`。

SLT 将 rs1 和 rs2 解释为二进制补码有符号整数进行比较。rs1 小于 rs2 时向 rd 写入1，否则写入0。

### 11.3 控制转移指令

先描述无条件跳转，再描述条件分支。控制转移不隐含线程同步或重汇合。

<a id="insn-jal"></a>

#### 11.3.1 JAL — PC 相对跳转并链接

```text
JAL rd, offset21
```

编码：**J 型**，opcode=`0x09`，funct=`0x00`。

JAL 将符号扩展后的 J 型字节偏移加到本条指令 PC 上，跳转到所得地址，并把后继指令地址 PC+8 写入 rd。以 r0 为目的寄存器时，链接值被丢弃，形成无条件跳转。

操作：

```text
target ← u32(pc + sext21(inst[51:32] << 1))
require target mod 8 == 0
R[rd] ← u32(pc + 8)
next_pc ← target
```

偏移基准是当前 PC。目标未对齐时不得写链接值；映射失败在下一次取指报告。rd=r0 可执行无条件跳转。

示例：`JAL r5, 16`。

<a id="insn-jalr"></a>

#### 11.3.2 JALR — 寄存器间接跳转并链接

```text
JALR rd, rs1, simm12
```

编码：**I 型**，opcode=`0x0a`，funct=`0x00`。

JALR 将符号扩展后的12位偏移加到 rs1 的旧值上，跳转到所得地址，并把 PC+8 写入 rd。与 RISC-V 的 JALR 不同，HELO 不清除目标地址的最低位；目标必须自然满足8字节对齐。

操作：

```text
target ← u32(a + sext12(imm12))
require target mod 8 == 0
R[rd] ← u32(pc + 8)
next_pc ← target
```

使用旧 rs1，即使 rd=rs1 也如此。不得自动清除最低位。目标未对齐不写链接；目标映射在下一次取指检查。

示例：`JALR r0, r5, 0`。

<a id="insn-br-eq"></a>

#### 11.3.3 BR.EQ — 条件分支 EQ

```text
BR.EQ rs1, rs2, offset13
```

编码：**B 型**，opcode=`0x08`，funct=`0x00`。

BR.EQ 比较 rs1 与 rs2。当 rs1 与 rs2 相等时，将符号扩展后的分支字节偏移加到本条指令 PC 上，并跳转到所得地址；否则继续执行 PC+8 处的指令。比较和跳转对各线程独立进行。

操作：

```text
if a == b:
    target ← u32(pc + sext13(inst[43:32] << 1))
    require target mod 8 == 0
    next_pc ← target
else:
    next_pc ← u32(pc + 8)
```

不写 GPR 或 FCSR。仅实际采用目标检查对齐；编码合法性始终检查。目标映射在下一次取指检查；分支不提供重汇合或线程同步。

示例：`BR.EQ r1, r2, -8`。

### 11.5 内存排序指令

本节只规定本版已有的访存完成等待，不扩展为 RISC-V 的其他 FENCE 模式。

<a id="insn-fence"></a>

#### 11.5.1 FENCE — 等待本线程先前访存

```text
FENCE
```

编码：**I 型**，opcode=`0x0c`，funct=`0x03`。

FENCE 等待本线程在程序顺序上先于它的访存完成后，才允许本线程继续执行。它不要求其他线程到达此处，不提供 warp 屏障。

操作：

```text
wait until all earlier memory accesses of current thread complete
next_pc ← u32(pc + 8)
```

rd、rs1、imm12 必须零。不等待其他线程，不更新 GPR/FCSR；不能替代 BARW，也不是跨 warp 屏障。

示例：`FENCE`。

### 11.6 整数乘法与除法指令

<a id="insn-mul"></a>

#### 11.6.1 MUL — 乘积低32位

```text
MUL rd, rs1, rs2
```

```text
product ← u32(a) * u32(b)  // 保留完整64位二进制补码/无符号位模式
R[rd] ← product[31:0]
```

#### 11.6.5 DIV — 有符号除法

```text
DIV rd, rs1, rs2
```

编码：**R 型**，opcode=`0x03`，funct=`0x04`。

DIV 将 rs1 除以 rs2，操作数按有符号整数解释，并将商写入 rd。商向零截断。除零以及有符号溢出的返回值见下列操作，不产生整数异常陷阱。

操作：

```text
if b == 0:
    result ← 0xffffffff
else if a == 0x80000000 and b == 0xffffffff:
    result ← 0x80000000
else:
    q ← trunc_toward_zero(i32(a) / i32(b))
    result ← q
R[rd] ← u32(result)
```

除零和有符号溢出均按伪代码返回确定值，不触发陷阱、不更新 FCSR。

示例：`DIV r3, r1, r2`。

#### 11.7.1 FADD — 浮点加法

```text
FADD rd, rs1, rs2, rm
```

操作：

```text
mode ← resolve_rm(ctrl, fcsr)
(result, flags) ← round32(fa + fb, mode)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

round32 按 §5 处理舍入、规范 NaN、次正规数和异常；非法静态/动态舍入模式不得提交结果。

```text
mode ← resolve_rm(ctrl, fcsr)
```

#### 11.7.10 FMIN — 浮点最小值

```text
FMIN rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x08`。

FMIN 选择两个 FP32 操作数中的较小值写入 rd。单个 NaN 不参与数值选择，两个操作数均为 NaN 时返回规范 NaN；正负零按本节规定的次序选择。

操作：

```text
flags ← NV if is_snan(a) or is_snan(b) else 0
if is_nan(a) and is_nan(b):
    result ← 0x7fc00000
else if is_nan(a):
    result ← b
else if is_nan(b):
    result ← a
else:
    result ← choose_less_fp_bits(a, b, negative_zero_before_positive_zero)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

ctrl 必须零。一个 NaN 时返回另一个操作数；两个 NaN 时返回规范 NaN。负零在此排序中小于正零；任一 signaling NaN 设置 NV。

#### 11.7.12 FCVT_I32_F32 — 浮点转有符号32位整数

```text
FCVT_I32_F32 rd, rs1, rm
```

编码：**R 型**，opcode=`0x06`，funct=`0x0e`。

FCVT_I32_F32 将 rs1 按binary32 浮点数解释，按指定舍入模式转换为32位有符号整数，把结果位模式写入 rd。转换是数值转换，不等同于移动位模式。超范围和 NaN 按 §5.2 返回饱和值并设置 NV。

操作：

```text
mode ← resolve_rm(ctrl, fcsr)
if is_nan(a):
    result ← 0x7fffffff; flags ← NV
else:
    integer ← round_to_integer(fa, mode)
    if integer below i32 range:
        result ← 0x80000000; flags ← NV
    else if integer above i32 range:
        result ← 0x7fffffff; flags ← NV
    else:
        result ← u32(integer)
        flags ← NX if integer != fa else 0
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

rs2 必须零。范围检查基于舍入后的数学整数；无效转换只设置 NV，不额外设置 NX。无穷按方向越界，NaN 按上界饱和。

示例：`FCVT_I32_F32 r3, r1, RTZ`。

<a id="insn-fcvt_f32_u32"></a>

#### 11.7.15 FCVT_F32_U32 — 无符号32位整数转浮点

```text
FCVT_F32_U32 rd, rs1, rm
```

编码：**R 型**，opcode=`0x06`，funct=`0x11`。

FCVT_F32_U32 将 rs1 按32位无符号整数解释，按指定舍入模式转换为binary32 浮点数，把结果位模式写入 rd。转换是数值转换，不等同于移动位模式。不能精确表示时累积 NX。

操作：

```text
mode ← resolve_rm(ctrl, fcsr)
(result, flags) ← round32(u32(a), mode)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

rs2 必须零。源按整数解释，进行数值转换；不是 MOV。不能精确表示时根据指定舍入模式取值并累计 NX。

示例：`FCVT_F32_U32 r3, r1, RNE`。

<a id="insn-fsgnj"></a>

#### 11.7.16 FSGNJ — 复制浮点符号

```text
FSGNJ rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x05`。

FSGNJ 保留 rs1 的指数和尾数，以rs2 的符号位作为结果符号，写入 rd。它是位模式操作，不执行浮点舍入，不设置浮点异常标志。

操作：

```text
sign ← b[31]
result ← (a AND 0x7fffffff) OR (sign << 31)
R[rd] ← result
```

ctrl 必须零。只操作位模式；保留 a 的全部尾数/指数和 NaN payload，即使源为 signaling NaN 也不设置异常。

示例：`FSGNJ r3, r1, r2`。

<a id="insn-fsgnjn"></a>

#### 11.7.17 FSGNJN — 复制取反符号

```text
FSGNJN rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x06`。

FSGNJN 保留 rs1 的指数和尾数，以rs2 符号位的反码作为结果符号，写入 rd。它是位模式操作，不执行浮点舍入，不设置浮点异常标志。

操作：

```text
sign ← NOT b[31]
result ← (a AND 0x7fffffff) OR (sign << 31)
R[rd] ← result
```

ctrl 必须零。只操作位模式；保留 a 的全部尾数/指数和 NaN payload，即使源为 signaling NaN 也不设置异常。

示例：`FSGNJN r3, r1, r2`。

<a id="insn-fsgnjx"></a>

#### 11.7.18 FSGNJX — 异或浮点符号

```text
FSGNJX rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x07`。

FSGNJX 保留 rs1 的指数和尾数，以rs1 与 rs2 符号位的异或作为结果符号，写入 rd。它是位模式操作，不执行浮点舍入，不设置浮点异常标志。

操作：

```text
sign ← a[31] XOR b[31]
result ← (a AND 0x7fffffff) OR (sign << 31)
R[rd] ← result
```

ctrl 必须零。只操作位模式；保留 a 的全部尾数/指数和 NaN payload，即使源为 signaling NaN 也不设置异常。

示例：`FSGNJX r3, r1, r2`。

<a id="insn-feq"></a>

#### 11.7.19 FEQ — 浮点相等比较

```text
FEQ rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x0a`。

FEQ 对 rs1、rs2 中的 binary32 值进行比较。当第一个操作数相等第二个操作数时，向 rd 写入整数1，否则写入0。任一操作数为 NaN 时结果为0，异常标志按各指令的比较规则设置。

操作：

```text
flags ← NV if is_snan(a) or is_snan(b) else 0
if is_nan(a) or is_nan(b):
    result ← 0
else:
    result ← bool32(fa == fb)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

ctrl 必须零；结果是整数0或1，正负零比较相等。quiet NaN 不设置 NV，signaling NaN 设置 NV。

示例：`FEQ r3, r1, r2`。

<a id="insn-flt"></a>

#### 11.7.20 FLT — 浮点小于比较

```text
FLT rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x0b`。

FLT 对 rs1、rs2 中的 binary32 值进行比较。当第一个操作数小于第二个操作数时，向 rd 写入整数1，否则写入0。任一操作数为 NaN 时结果为0，异常标志按各指令的比较规则设置。

操作：

```text
flags ← NV if is_nan(a) or is_nan(b) else 0
if is_nan(a) or is_nan(b):
    result ← 0
else:
    result ← bool32(fa < fb)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

ctrl 必须零；结果是整数0或1，正负零比较相等。任意 NaN 都设置 NV。

示例：`FLT r3, r1, r2`。

<a id="insn-fle"></a>

#### 11.7.21 FLE — 浮点小于等于比较

```text
FLE rd, rs1, rs2
```

编码：**R 型**，opcode=`0x06`，funct=`0x0c`。

FLE 对 rs1、rs2 中的 binary32 值进行比较。当第一个操作数小于等于第二个操作数时，向 rd 写入整数1，否则写入0。任一操作数为 NaN 时结果为0，异常标志按各指令的比较规则设置。

操作：

```text
flags ← NV if is_nan(a) or is_nan(b) else 0
if is_nan(a) or is_nan(b):
    result ← 0
else:
    result ← bool32(fa <= fb)
R[rd] ← result
fcsr.fflags ← fcsr.fflags OR flags
```

ctrl 必须零；结果是整数0或1，正负零比较相等。任意 NaN 都设置 NV。

示例：`FLE r3, r1, r2`。

<a id="insn-fclass"></a>

#### 11.7.22 FCLASS — 浮点分类

```text
FCLASS rd, rs1
```

编码：**R 型**，opcode=`0x06`，funct=`0x0d`。

FCLASS 根据 rs1 的 binary32 位模式进行分类，向 rd 写入仅一位置1的分类位图。十个分类位的定义见 §5.3；高22位为零，源值不被修改。

操作：

```text
class_bit ← classify_binary32(a)  // §5.3 对应0–9
R[rd] ← 1 << class_bit
```

rs2 和 ctrl 必须零；返回十类之一的 one-hot 位图，高22位为零，不更新 FCSR。分类使用位模式，不以宿主浮点比较替代 NaN 分类。

示例：`FCLASS r3, r1`。

### 11.8 控制与状态寄存器指令

六条 CSR 指令均为特殊 I 型，寄存器源形式和立即数源形式共享同一 CSR 地址空间。读写抑制与权限见 §8.2。

<a id="insn-csrrw"></a>

#### 11.8.1 CSRRW — 替换 CSR（寄存器）

```text
CSRRW rd, csr12, rs1
```

编码：**I 型**，opcode=`0x0c`，funct=`0x07`。

CSRRW 将指定 CSR 的旧值返回到 rd，并以 rs1 的旧值替换 CSR 的可写值。rd=r0 时不发生 CSR 读取，但写入仍然发生；零源表示写零。

操作：

```text
v ← R[rs1]
require csr12 is defined
require csr12 is writable
if rd != r0:
    old ← CSR[csr12]
CSR[csr12] ← v
if rd != r0:
    R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终写 CSR；rd=r0 抑制读取，源为零仍写零。rd 与 rs1 重叠时，先捕获旧源。

示例：`CSRRW r3, 0x000, r1`。

<a id="insn-csrrs"></a>

#### 11.8.2 CSRRS — 置位 CSR（寄存器）

```text
CSRRS rd, csr12, rs1
```

编码：**I 型**，opcode=`0x0c`，funct=`0x08`。

CSRRS 读取指定 CSR，将旧值返回到 rd，并把 rs1 的旧值作为位掩码，置位掩码中为1的可写位。只有源寄存器编号 rs1=r0 才抑制写入；其他寄存器即使保存零，也属于写访问。

操作：

```text
v ← R[rs1]
require csr12 is defined
if rs1 != r0: require csr12 is writable
old ← CSR[csr12]
if rs1 != r0:
    CSR[csr12] ← old OR v
R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终读取 CSR；仅 rs1 编号为 r0 才抑制写入，非零编号保存零仍须检查写权限。rd 与 rs1 重叠时，先捕获旧源。

示例：`CSRRS r3, 0x000, r1`。

<a id="insn-csrrc"></a>

#### 11.8.3 CSRRC — 清位 CSR（寄存器）

```text
CSRRC rd, csr12, rs1
```

编码：**I 型**，opcode=`0x0c`，funct=`0x09`。

CSRRC 读取指定 CSR，将旧值返回到 rd，并把 rs1 的旧值作为位掩码，清除掩码中为1的可写位。只有源寄存器编号 rs1=r0 才抑制写入；其他寄存器即使保存零，也属于写访问。

操作：

```text
v ← R[rs1]
require csr12 is defined
if rs1 != r0: require csr12 is writable
old ← CSR[csr12]
if rs1 != r0:
    CSR[csr12] ← old AND u32(NOT v)
R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终读取 CSR；仅 rs1 编号为 r0 才抑制写入，非零编号保存零仍须检查写权限。rd 与 rs1 重叠时，先捕获旧源。

示例：`CSRRC r3, 0x000, r1`。

<a id="insn-csrrwi"></a>

#### 11.8.4 CSRRWI — 替换 CSR（立即数）

```text
CSRRWI rd, csr12, zimm5
```

编码：**I 型**，opcode=`0x0c`，funct=`0x0a`。

CSRRWI 将指定 CSR 的旧值返回到 rd，并以零扩展的5位 zimm替换 CSR 的可写值。rd=r0 时不发生 CSR 读取，但写入仍然发生；零源表示写零。

操作：

```text
require inst[23:21] == 0
zimm ← inst[20:16]
v ← zext5(zimm)
require csr12 is defined
require csr12 is writable
if rd != r0:
    old ← CSR[csr12]
CSR[csr12] ← v
if rd != r0:
    R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终写 CSR；rd=r0 抑制读取，源为零仍写零。立即数范围0–31，inst[23:21] 非零非法。

示例：`CSRRWI r3, 0x000, 31`。

<a id="insn-csrrsi"></a>

#### 11.8.5 CSRRSI — 置位 CSR（立即数）

```text
CSRRSI rd, csr12, zimm5
```

编码：**I 型**，opcode=`0x0c`，funct=`0x0b`。

CSRRSI 读取指定 CSR，将旧值返回到 rd，并把零扩展的5位 zimm作为位掩码，置位掩码中为1的可写位。zimm=0 时只读，不写 CSR。

操作：

```text
require inst[23:21] == 0
zimm ← inst[20:16]
v ← zext5(zimm)
require csr12 is defined
if zimm != 0: require csr12 is writable
old ← CSR[csr12]
if zimm != 0:
    CSR[csr12] ← old OR v
R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终读取 CSR；zimm=0 时不写，因此可读只读 CSR；rd=r0 只丢弃结果。立即数范围0–31，inst[23:21] 非零非法。

示例：`CSRRSI r3, 0x000, 31`。

<a id="insn-csrrci"></a>

#### 11.8.6 CSRRCI — 清位 CSR（立即数）

```text
CSRRCI rd, csr12, zimm5
```

编码：**I 型**，opcode=`0x0c`，funct=`0x0c`。

CSRRCI 读取指定 CSR，将旧值返回到 rd，并把零扩展的5位 zimm作为位掩码，清除掩码中为1的可写位。zimm=0 时只读，不写 CSR。

操作：

```text
require inst[23:21] == 0
zimm ← inst[20:16]
v ← zext5(zimm)
require csr12 is defined
if zimm != 0: require csr12 is writable
old ← CSR[csr12]
if zimm != 0:
    CSR[csr12] ← old AND u32(NOT v)
R[rd] ← old
```

整个操作按 §8.2 和 §9 一次提交。始终读取 CSR；zimm=0 时不写，因此可读只读 CSR；rd=r0 只丢弃结果。立即数范围0–31，inst[23:21] 非零非法。

示例：`CSRRCI r3, 0x000, 31`。

### 11.9 HELO 线程控制与同步指令

本节为 HELO 的任务退出、诊断及 warp 屏障定义，不对应 RISC-V 特权态或系统调用。

<a id="insn-exit"></a>

#### 11.9.1 EXIT — 退出当前参与线程

```text
EXIT
```

编码：**I 型**，opcode=`0x0c`，funct=`0x01`。

EXIT 终止当前参与线程，清除对应 live_mask 位并停止该线程的后续取指。全部任务线程退出后，任务完成。退出不会改变固定的 launch_mask。

操作：

```text
if any BARW round is pending in this warp:
    error barrier_protocol
clear current thread bit from live_mask
stop fetching for current thread
if every task thread has exited:
    task completes
```

rd、rs1、imm12 必须零。launch_mask 不变；有线程退出后其余线程再执行 BARW 属于协议错误。EXIT 没有可观察的后继取指，不规定退出线程 PC 的新值。

示例：`EXIT`。

<a id="insn-trap"></a>

#### 11.9.2 TRAP — 显式诊断陷阱

```text
TRAP code12
```

编码：**I 型**，opcode=`0x0c`，funct=`0x02`。

TRAP 产生显式陷阱，以12位无符号立即数作为诊断编号。任务停止并锁存错误；本版不定义程序内陷阱处理程序或返回指令。

操作：

```text
error explicit_trap, diagnostic_code ← zext12(imm12)
```

rd、rs1 必须零。诊断号范围0–4095；任务停止并锁存错误，本条不提交 GPR/FCSR/存储或正常 PC 前进。无程序内陷阱处理。

示例：`TRAP 7`。

<a id="insn-barw"></a>

#### 11.9.3 BARW — 固定参与集合 warp 屏障

```text
BARW
```

编码：**I 型**，opcode=`0x0c`，funct=`0x04`。

BARW 对 launch_mask 中的固定线程集合执行可重复使用的 warp 屏障。到达线程停在屏障 PC；全部参与者到达同一位置且其先前访存完成后，解除等待并继续执行后继指令。

操作：

```text
require live_mask == launch_mask
if no round pending:
    barrier_pc ← pc; arrived_mask ← 0
else:
    require barrier_pc == pc
record current thread bit in arrived_mask
wait at barrier_pc
if arrived_mask == launch_mask and prior accesses of all participants complete:
    release all participants
    set their next_pc ← u32(barrier_pc + 8)
    clear round state
```

rd、rs1、imm12 必须零。不同 BARW PC、提前退出或等待期间 EXIT 都是协议错误。记录到达后 PC 暂停；后续轮次错误不回滚此前已成功登记的到达，见 §7.1 和 §9。

示例：`BARW`。
